# TP 5 — Étape 3 : Éprouver

**Projet :** Seconde Vie
**Périmètre :** modules Dons et Objets
**Base de travail :** modèle et écrans retenus au TP 4, sans les corriger à cette étape.

---

## 0. Rappel de la conception utilisée pour les tests

Pour cette étape, on conserve les choix du TP 4 :

### Fiches prévues dans le modèle

- **Don :** identifiant, nom du donateur, demande de reçu.
- **Objet :** identifiant, désignation, catégorie, état, localisation, prix de vente, statut de vente.
- **Catégorie :** nom, prix de base.

### Relations prévues

- Un don peut contenir plusieurs objets. Chaque objet est rattaché à un seul don.
- Une catégorie peut regrouper plusieurs objets. Chaque objet appartient à une seule catégorie.

### Écrans prévus

1. Liste des objets.
2. Fiche d'un objet.
3. Gestion des dons.

**Important :** le modèle du TP 4 ne contient pas de fiche Donateur indépendante ni de fiche Vente. Le nom du donateur est enregistré directement dans la fiche Don, et la vente est représentée par le statut de l'objet. On conserve cette conception pour l'éprouver ; on ne la modifie pas maintenant.

### Conventions utilisées dans les tableaux

- Les identifiants `D-001`, `OBJ-001`, etc. sont des identifiants provisoires utilisés uniquement pour distinguer les fiches pendant le test.
- **Non précisé** signifie que le scénario ne donne pas cette information.
- Aucune liste de catégories, aucun prix de base et aucune grille de prix selon l'état ne sont fournis dans les cas. On ne les invente donc pas.
- Pour les objets reçus avant la vente, le statut est indiqué comme **non vendu à ce stade**. Dans le cas 3, les deux objets concernés passent au statut **vendu**.

# 2. Saisir — wireframes des écrans du TP 4

Les wireframes ci-dessous représentent uniquement les trois écrans retenus au TP 4. Ils ne créent pas de nouvel écran Donateur ou Vente.

## Écran 1 — Liste des objets

**Utilité :** consulter les objets enregistrés et retrouver leur catégorie, leur état, leur localisation, leur prix et leur statut de vente.
**Utilisateur :** bénévole.
**Stories :** US01, US02 et US03.

```text
+--------------------------------------------------------------------------------+
|                              LISTE DES OBJETS                                  |
+--------------------------------------------------------------------------------+
|                                                                                |
|  [ Ajouter un objet ]                                                         |
|                                                                                |
|  Identifiant | Désignation | Catégorie | État | Localisation | Prix | Statut  |
|  ------------|-------------|-----------|------|--------------|------|---------|
|  OBJ-001     | Table       | Non définie| Bon | Non précisée | N/C  | Vendu*  |
|  OBJ-002     | Vase        | Non définie| Neuf| Non précisée | N/C  | Non vendu|
|  OBJ-003     | Lampe       | Non définie| Usée| Non précisée | N/C  | Non vendu|
|  OBJ-004     | Aquarium    | Non définie| Bon | Non précisée | N/C  | Non vendu|
|  OBJ-005     | Chaise      | Non définie| N/P | Non précisée | N/C  | Vendu*  |
|                                                                                |
|  Pour chaque ligne : [ Consulter l'objet ]                                    |
|                                                                                |
+--------------------------------------------------------------------------------+
```

`N/C` signifie « non calculable » et `N/P` signifie « non précisé ». Les statuts de la table et de la chaise correspondent au cas 3 ; les autres objets ne sont pas indiqués comme vendus dans les cas.

## Écran 2 — Fiche d'un objet

**Utilité :** enregistrer, consulter ou modifier un objet. Le prix de vente dépend du prix de base de la catégorie et de l'état.
**Utilisateur :** bénévole.

```text
+--------------------------------------------------------------+
|                       FICHE D'UN OBJET                       |
+--------------------------------------------------------------+
| Identifiant : [ attribué à l'objet ]                          |
|                                                              |
| Désignation : [________________________________________]     |
|                                                              |
| Catégorie :   [ choisir une catégorie                   v ]  |
|                                                              |
| État :        [ choisir l'état                          v ]  |
|                                                              |
| Localisation :[________________________________________]     |
|                                                              |
| Prix de base de la catégorie : [ valeur affichée ]           |
|                                                              |
```

Les choix disponibles pour les catégories et les états ne sont pas fournis dans les cas. Le prix calculé ne peut donc pas être renseigné tant que les catégories, les prix de base et la règle de calcul ne sont pas définis.

## Informations absentes des scénarios, mais champs déjà prévus

Les éléments suivants ne constituent pas, à eux seuls, un défaut de conception : les écrans possèdent déjà les champs nécessaires, mais les cas ne donnent pas leurs valeurs.

- **Localisation :** aucune localisation n'est indiquée pour les objets. Le bénévole devra la renseigner lors de l'enregistrement ou du rangement.
- **Demande de reçu :** aucun des trois cas ne précise si le donateur souhaite un reçu. Il faut demander le choix au donateur au moment du don.
- **État de la chaise :** le cas 3 ne donne pas son état. Il faudra l'évaluer lors de la réception ; on ne peut pas l'inventer pour le test.
- **Date exacte de la vente :** seul « samedi » est indiqué. Le modèle actuel ne stocke pas de date de vente et les besoins fournis ne disent pas explicitement si elle doit être conservée.

# 5. Bilan de l'épreuve

Les trois écrans du TP 4 permettent de saisir un don, d'enregistrer les objets qui le composent, de renseigner leur état et leur localisation, puis de marquer individuellement les objets comme vendus.

Les tests révèlent cependant plusieurs points à traiter à l'étape 4 :

1. Les catégories et les règles de prix doivent être précisées pour pouvoir calculer les prix de vente.
2. Il faut décider si une fiche Donateur indépendante est réellement nécessaire ou si le nom dans la fiche Don suffit.
3. Le cas de vente fait apparaître le besoin de représenter une vente regroupant plusieurs objets, alors que le modèle actuel ne suit que le statut de chaque objet.
4. La règle « un objet vendu ne revient pas en stock » doit être protégée dans les possibilités de modification.

**Aucune de ces corrections n'est appliquée dans cette étape 3.** Elles sont uniquement relevées et classées pour être reprises à l'étape 4.
